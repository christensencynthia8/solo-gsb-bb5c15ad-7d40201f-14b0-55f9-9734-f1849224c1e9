# 字幕校稿对齐（Subtitle Proofreading Aligner）

把**逐行对白稿**与 **SRT 字幕**自动对位的 Web 小工具：解析并保留 SRT 时间码，
对两侧文本做去空白/去标点的归一化，以**归一化字符编辑距离**为匹配代价、
**跳过任一条计 0.45**，求**全局单调、最低代价**的对齐。两侧条目各最多匹配一次、
允许缺项；重复短句也严格按整段顺序匹配。可填写**人工锚点**把确定对应的
「行:块」强制配对，锚点之间仍自动对齐。页面并排显示对位/缺项/锚点行与时间码，
可一键下载含全部状态的 CSV。

另内置 **SRT 时间轴重定时**工具：输入原 SRT 与若干「原时间 → 目标时间」校准点，
按**分段线性映射**整体重排时间轴（区间外按最近区段斜率外推，单点时整体平移），
页面预览原/新时间码，可下载保留字幕正文并重新编号的 SRT。

还内置 **SRT 断行排版**工具：粘贴 SRT 并设置每行最大显示宽度（12～60），
逐块把正文排成**最多两行**——东亚宽字符计 2、其余计 1，组合字符不与前字拆开、
连续拉丁单词不拆分；枚举全部合法断点，按**句末标点优先、两行宽度均衡**选优
（非固定字数贪心），无合法排法的块保留原正文并标记人工处理。预览原文/结果/状态，
下载的 SRT **保持原时间码与文字内容，仅调整换行**。

另有 **SRT 时间避让**工具：输入 SRT、最小块间隔与单块最大平移量，整体平移修整
**重叠或间隔过短**的相邻字幕块——保持每块**时长、顺序与正文**不变，在非负时间与
平移上限内，先求**全段最大绝对平移量最小**的可行时间轴，平移量相同时再让各块
**按原入点就近**落位（整体求解，不做逐块贪心，避免把冲突推给后面的块）。
页面预览原/新时间码与各块平移量；约束无法满足时**指出首个冲突块并禁止导出**，
可行时可下载修整后的 SRT。

还有 **双语 SRT 拆轨**工具：输入每块恰好两行（一行中文、一行英文）的双语 SRT，
按**错配计分**（汉字落在英文轨、拉丁字母落在中文轨各计 1 分，相邻块中英行
上下顺序变化另计 2 分）以**全段最小总代价**的动态规划确定每块归属，平局逐块
优先「中文在上」。页面并排预览两轨归属与总错配分，可分别下载**保留原时间码与
正文行内容、从 1 重编号**的中文轨 / 英文轨 SRT；正文行数不符的块会指出块号并
拒绝导出。

另有 **SRT 版本差异审校**工具：输入旧版与新版 SRT，按块序做**全局最小代价**
对齐，允许 1:1、1:2（拆分）、2:1（合并）与单侧缺项（增删）；候选先合并正文
再做同样的文本归一化，以归一化编辑距离计分，拆并另加 0.1、增删各计 0.45，
总分相同时优先入出点偏差更小、再优先 1:1。结果标出**未变 / 新增 / 删除 /
仅改时 / 文字改动 / 拆分 / 合并**，并排显示两侧时间码与正文，可下载 UTF-8 CSV。

另有 **剪辑字幕重建**工具：输入原 SRT 与 JSON 剪辑数组（每项含非负整数毫秒
`source_in` / `source_out` / `target_in`，出点须大于入点；片段可乱序、重复、
目标区间可重叠），把每个字幕与每段素材区间按**左闭右开**求交、裁切后按**原速**
平移到目标位置；以映射后全部端点切分时间轴，同一时刻有效的原块按**解析序位**
拼接、保留各块正文换行；同一原块被多片段覆盖时只显示一次，直到最后一份覆盖结束
才移除。仅合并相邻且有效块集合相同的区间、跳过无字幕区间，导出按时间从 1 编号的
无重叠 SRT。页面预览目标时间码、原块序位与正文；非法剪辑清单**指出项号并禁止
导出**。

后端 Python + FastAPI，前端原生 HTML / CSS / JavaScript（无框架、无构建步骤）。

## 一键启动（推荐：Docker Compose）

需要本机已安装 Docker 与 Docker Compose（`docker compose version` 可用）。
**单条命令**即可完成镜像构建、依赖安装与初始化，随后在后台启动服务：

```bash
docker compose up -d --build
```

无需额外建库、迁移或初始化脚本；依赖安装与应用启动均随上述命令完成，
健康检查通过后即可访问：

```
http://localhost:8000
```

- 访问端口：默认宿主机 **8000**（容器内固定监听 8000）。
- 端口配置：通过环境变量 `APP_PORT` 修改宿主机映射端口，详见
  [下一节](#修改端口)。

停止：

```bash
docker compose down
```

### 修改端口

默认占用宿主机 **8000** 端口。改为其它端口有两种方式：

```bash
# 方式一：环境变量临时覆盖
APP_PORT=9000 docker compose up -d --build

# 方式二：复制 .env.example 为 .env 后修改 APP_PORT
cp .env.example .env
# 编辑 .env：APP_PORT=9000
docker compose up -d --build
```

容器内固定监听 8000，仅宿主机映射端口可改（`docker-compose.yml` 中
`"${APP_PORT:-8000}:8000"` 冒号左侧）。

## 使用方法

1. 左侧文本框粘贴**逐行对白稿**（每行一句，空行忽略）。
2. 右侧文本框粘贴标准 **SRT**（`序号 / 时间码入点 --> 出点 / 字幕文本`，块间空行分隔）。
3. 可调整「跳过单条代价」（默认 **0.45**，范围 0~1）。
4. （可选）在「**人工锚点**」框填写若干 `行:块` 强制配对，详见
   [下一节](#人工锚点强制配对)。
5. 点 **开始对齐**，下方并排展示结果表：
   - **对位**（绿）：对白稿行与字幕行成功匹配，显示逐行匹配代价；
   - **缺对白稿**（红）：SRT 有该字幕、对白稿缺这一条；
   - **缺字幕**（黄）：对白稿有这句、SRT 中缺失；
   - **锚点**（紫色徽标/底色）：人工指定的强制配对行。
   - 每行都带有对白稿行号、SRT 序号与保留下来的**入点/出点时间码**。
6. 点 **下载 CSV** 导出含状态、代价、行号、文本、时间码的结果（UTF-8 带 BOM，
   Excel 直接打开不乱码）；提供锚点时 CSV 末尾增加「锚点」列标出锚点行。

页面右上/输入框标题旁的「填入示例」可快速体验，其中特意包含缺项与重复短句。

## SRT 时间轴重定时

页面顶部切换到「**SRT 时间轴重定时**」选项卡，可按校准点整体重排字幕时间轴：

1. 左侧文本框粘贴**原 SRT**（与对齐工具同一解析器，保留时间码与正文）。
2. 右侧文本框按顺序填写**校准点**，每行一个：`原时间 --> 目标时间`
   （也接受空白分隔），例如：

   ```
   00:00:01,000 --> 00:00:02,000
   00:00:07,000 --> 00:00:10,500
   ```

   - 时间码格式 `HH:MM:SS,mmm`（毫秒可省略，分隔符 `,` / `.` 均可）；
   - **两列时间都必须严格递增**（原时间列、目标时间列各自递增），
     否则返回 400 并指出第几个校准点；
   - 至少一个校准点，最多 500 个。
3. 点 **开始重定时**，下方表格逐块预览：新编号、原序号、原时间码、
   **新时间码**与字幕文本。
4. 点 **下载 SRT** 导出重定时后的字幕：**保留字幕正文**（含多行原文），
   序号从 1 **重新编号**。

### 映射规则

- 相邻校准点之间，对每个字幕块的**入点、出点**分别做**分段线性映射**
  （区间内线性插值，校准点处精确命中目标时间）；
- 首/末校准点之外，**沿用最近区段的斜率外推**；
- **只有一个校准点时整体平移**（所有时间加上 目标 − 原 的固定偏移）；
- 所有结果统一**取整到毫秒**（四舍五入）。

### 导出前校验（拒绝导出）

映射完成后逐块检查，任一不满足即返回 **400**、指出**具体块号**并拒绝导出：

- **负时间**：映射后入点/出点小于 0（常见于首校准点之前外推过多）；
- **入点不早于出点**：映射后入点 ≥ 出点（如时长被压缩到 0）；
- **字幕入点顺序倒退**：某块入点早于前一块入点（原 SRT 顺序错乱时也会触发）。

错误信息示例：`重定时结果校验失败：第 1 块映射后出现负时间（-00:00:00,300 --> -00:00:00,100）`。

## SRT 断行排版

页面顶部切换到「**SRT 断行排版**」选项卡，可在不改动时间码与文字的前提下，
为每个字幕块重新安排正文换行：

1. 文本框粘贴标准 **SRT**（与对齐/重定时同一解析器，保留序号与时间码）。
2. 设置「**每行最大显示宽度**」（整数，范围 **12～60**，默认 30）。
3. 点 **开始排版**，下方表格逐块预览：**状态**、序号、时间码、**原文**与
   **排版结果**（结果中的换行位置以 ↵ 标出）。
4. 点 **下载 SRT** 导出：**原序号、入点/出点时间码与文字内容全部保持不变，
   只有正文里的换行位置可能变化**。

汇总区分别统计：**单行**（整段一行放得下，保持一行）、**两行**（已重新断行）、
**需人工处理**（无合法排法、保留原正文）。

### 排版规则

- 每个字幕块正文排成**最多两行**；整段一行能放下时保持一行。
- **显示宽度**：东亚宽字符（East Asian Width W/F，如中日韩文字、全角标点）
  计 **2**，其余字符计 **1**；**组合字符**（Unicode 类别 M，如重音符）计 0，
  且**必须附着在前字之后，不可拆开**。
- **连续拉丁字母构成的单词不可拆分**：连续的拉丁/希腊/西里尔字母与数字视作
  一个词，撇号连接的 `don't`、`l'amour` 同样作为整体。
- **合法断点**只有两类：① 空白处（断行后该处空白折叠丢弃）；
  ② 两个相邻词组之间（如中日韩字之间、字与词之间）。
- **枚举全部合法断点**，过滤掉任一行超出宽度上限的排法，再综合
  **句末标点优先**（句末 `。！？….!?` 及其闭合引号 > 句中 `，、；：` 等 >
  无标点）与**两行宽度均衡**（宽度差最小，平局时首行更满）选择最优排法；
  **不做固定字数贪心截断**。
- **无合法两行排法**（如单词本身超过整行宽度，或两行都无法容纳）的块：
  **保留原正文不动**并标记「**需人工处理**」，结果表给出具体原因，
  导出 SRT 时这些块也原样输出。
- 原块内多行正文会先还原为整句再排版（窄体字母/数字跨原行相接时补一个空格，
  中日韩文字直接相接），文字内容不增删。

示例（每行宽度上限 30）：

```
你好，世界！今天我们来聊聊字幕断行排版。
        ↓
你好，世界！
今天我们来聊聊字幕断行排版。
```

## SRT 时间避让

页面顶部切换到「**SRT 时间避让**」选项卡，可整体平移修整重叠或间隔过短的
相邻字幕块：

1. 文本框粘贴标准 **SRT**（与其它工具同一解析器，保留序号、时间码与正文）。
2. 设置「**最小块间隔**」（整数毫秒，**0～60000**，默认 0：相邻块出点到
   下一块入点的最小距离）与「**单块最大平移量**」（整数毫秒，
   **0～3600000**，默认 2000：每块入点允许移动的最大绝对距离）。
3. 点 **开始避让**，下方表格逐块预览：新编号、原序号、**原时间码**、
   **新时间码**、**平移量**（正为后移、负为前移）与字幕文本；
   被平移的块以底色标出。
4. 点 **下载 SRT** 导出修整后的字幕：**保留字幕正文**（含多行原文），
   序号从 1 **重新编号**。

### 避让规则

- 每块**时长、顺序与正文不变**，仅整体平移；新入点不为负。
- 修整后相邻块间隔（上块出点 → 下块入点）≥ 最小块间隔。
- 每块 |平移量| ≤ 单块最大平移量。
- 在上述约束下**全段整体求解**（非逐块贪心，避免把冲突推给后面的块）：
  1. 先使**全段最大绝对平移量最小**（二分平移量 + 前向最早可行判定）；
  2. 最大平移量相同的可行时间轴中，取**各块平移量绝对值之和最小**者——
     即每块按原入点就近落位（化为带单调盒约束的 L1 保序回归精确求解）。
- **时长非正**（入点不早于出点）的块无法仅通过平移修整，直接报错指出块号。
- 约束无法满足（平移上限内不存在可行时间轴）时，返回 **400** 并指出
  **首个冲突块**（前向最早可行入点首次超出其平移上限的块），
  预览与导出同样被拒绝。

错误信息示例：`时间避让失败：第 2 块无法排入时间轴：为满足与前一块的最小间隔，其入点最早为 00:00:00,500，已超出平移上限允许的最晚入点 00:00:00,200（原入点 00:00:00,100，单块最大平移量 100 毫秒）。请增大单块最大平移量或减小最小块间隔`

## 双语 SRT 拆轨

启动后浏览器打开 **http://localhost:8000**（Docker Compose 一键启动见上文，
端口可改），页面顶部切换到「**双语 SRT 拆轨**」选项卡，可把每块恰好两行的
双语字幕（一行中文、一行英文）拆成两条独立字幕轨：

1. 文本框粘贴标准 **SRT**（与其它工具同一解析器，保留序号、时间码与正文行），
   **每个字幕块正文必须恰好两行**。
2. 点 **开始拆轨**，下方表格逐块并排预览：新编号、原序号、时间码、
   **轨序**（中文在上 / 英文在上，轨序与上一块不同的带 ⇄+2 标记）、
   **中文轨**与**英文轨**各自分得的正文行，以及本块错配字符数。
3. 汇总区显示：字幕块数、**错配字符**总数、**顺序变化**次数与**总错配分**。
4. 点 **下载中文轨 SRT** / **下载英文轨 SRT** 分别导出两轨：**保留原时间码与
   正文行内容**，序号从 1 **重新编号**。

### 拆轨规则

- 每块的两行分别归入中文轨与英文轨，归属只有两种：**中文在上**（上行入中文轨）
  或**英文在上**（上行入英文轨）。
- **错配计分**：汉字落在英文轨、拉丁字母落在中文轨，**每个字符各计 1 分**
  （全角拉丁字母同样计为拉丁字母；希腊/西里尔字母不算）；数字、标点等
  中性字符不计分。
- 相邻两块的中英行**上下顺序发生变化，另计 2 分**。
- 每块归属由**全段总代价最小**的动态规划确定（非逐块贪心）：先求各块两种
  归属的错配，再在整段上最小化「错配字符 + 顺序变化 × 2」。
- 总代价相同的方案中，**从第 1 块起逐块优先「中文在上」**——纯数字/标点等
  中性行因此依邻块保持轨序稳定，不会无意义地来回翻转。
- **正文行数不符**（不是恰好两行）的块：返回 **400** 并**指出块号**
  （声明序号与顺序不一致时一并给出），预览与导出同样被拒绝。

错误信息示例：`拆轨失败：第 2 块正文须恰好两行（实际 1 行），无法拆轨`

## SRT 版本差异审校

页面顶部切换到「**SRT 版本差异审校**」选项卡，可比较同一字幕的新旧两版：

1. 左/右文本框分别粘贴**旧版 SRT** 与**新版 SRT**（与其它工具同一解析器，
   保留序号、时间码与正文）。
2. 点 **开始比较**，下方表格按块序展示对齐结果，每行标出七种状态之一：
   **未变**（绿）、**仅改时**（紫）、**文字改动**（黄）、**拆分**（青，
   旧 1 块 → 新 2 块）、**合并**（橙，旧 2 块 → 新 1 块）、**新增**（蓝）、
   **删除**（红）；每行并排显示两侧序号、入点/出点时间码与正文，
   配对行附**入出点偏差**（毫秒）。
3. 点 **下载 CSV** 导出全部结果（UTF-8 带 BOM，Excel 直接打开不乱码）。

### 对齐与计分规则

- 按块序做**全局最小代价**对齐（Needleman–Wunsch 风格 DP），每步可以是
  1:1、1:2（拆分）、2:1（合并）或单侧缺项（增删），两版块序均保持单调、
  每块恰好消费一次。
- 候选**先合并正文再归一化**（与其它工具相同的 NFKC + 小写折叠 +
  去空白/标点），以**归一化编辑距离**计文本分；拆并在文本分外**另加 0.1**，
  增删（单侧缺项）各计 **0.45**。
- 总分相同的方案，优先**入出点偏差**（两侧入点差 + 出点差，毫秒）更小者，
  再优先 **1:1**（拆并次数更少）——即 DP 关键字为
  （总分, 入出点偏差, 拆并次数）的字典序。
- 状态判定：1:1 配对中正文完全一致且时间码一致为**未变**，仅时间码不同为
  **仅改时**，正文不同为**文字改动**；拆分/合并按结构标记
  （即使合并后正文归一化相同）。

## 剪辑字幕重建

页面顶部切换到「**剪辑字幕重建**」选项卡，可按剪辑清单把一条素材 SRT 裁切、
平移，重建出成片时间轴上的字幕：

1. 左侧文本框粘贴**原 SRT**（与其它工具同一解析器，保留时间码与正文换行）。
2. 右侧文本框填写 **JSON 剪辑数组**，每项描述一段素材及其在成片中的位置，
   三个字段均为**非负整数毫秒**：

   | 字段 | 含义 |
   | --- | --- |
   | `source_in` | 素材入点（左闭） |
   | `source_out` | 素材出点（右开，**必须严格大于** `source_in`） |
   | `target_in` | 该片段在成片时间轴上的入点（左闭） |

   例如（片段乱序、末尾还有一段重复使用的素材）：

   ```json
   [
     {"source_in": 0,    "source_out": 5000,  "target_in": 0},
     {"source_in": 9000, "source_out": 13000, "target_in": 5000},
     {"source_in": 4000, "source_out": 8000,  "target_in": 9000},
     {"source_in": 9000, "source_out": 11000, "target_in": 8000}
   ]
   ```

3. 点 **开始重建**，下方表格预览：**新序号、目标时间码、命中的原块解析序位**
   （以标签列出）与**正文**（块内/块间换行以 ↵ 标出）。汇总区显示重建字幕数、
   剪辑段数与覆盖块次。
4. 点 **下载 SRT** 导出：序号从 1 重新编号、彼此**无重叠**的成片字幕。

### 重建规则

- 片段**不要求按素材顺序、允许重复使用**，`target_in` 也可任意安排，因此成片
  区间**允许重叠**；每段一律按**原速**映射
  （`目标时间 = target_in + 源时间 − source_in`）。
- 每个原字幕块与每段素材区间求交，区间一律**左闭右开**：仅取
  `max(字幕入, source_in) ~ min(字幕出, source_out)`，裁切后整体平移；
  交集为空（含端点恰好相碰）直接丢弃。
- 以**映射后的全部端点**切分时间轴：每个时间片内，把当前有效的原字幕块按
  **解析序位**（SRT 中块出现的先后）排列，各块**保留自身正文换行**，块与块之间
  再以一个换行连接。
- **同一原块被多个片段覆盖时只显示一次**：按覆盖份数计数，直到**最后一份覆盖
  结束**才移除——因此重叠/相接的重复片段会自然拼成连续的一段，正文不会重复。
- **仅合并时间上相邻且有效原块集合相同的区间**（集合在边界两侧不同则不合并）；
  **没有任何有效字幕的时间片直接跳过**，不产生空字幕。
- 输出严格按目标时间排序，序号从 1 编号，相邻区间无重叠（可首尾相接）。

### 非法清单（拒绝预览与导出）

剪辑清单的一切校验错误均返回 **400** 并**指出项号**（从 1 开始），预览与下载
同样被禁止：不是数组 / 数组为空、某项不是对象、缺字段、字段不是整数（含 `1.5`、
`true`、字符串）、出现负值、`source_out ≤ source_in`；剪辑段数超过 2000 也会
拒绝。原 SRT 本身非法时返回 `SRT 解析失败：…`。

错误信息示例：`剪辑清单第 2 项出点 5 须大于入点 5（区间左闭右开，不可为空）`。

## 人工锚点（强制配对）

自动对齐在个别位置不符合预期时，可人工指定若干锚点把确定对应的两行强行配对：

- **输入格式**：`对白稿行序位:SRT块序位`，多对之间用逗号、分号或空格分隔，
  冒号中英文均可，例如 `3:3, 10:8`、`1：1 6：5`。
- **序位定义**：均从 **1** 开始，指**解析后**条目在各自序列中的序位——
  对白稿即非空行的行号，SRT 即字幕块的块序位（与结果表两列 `#` 一致）。
- **校验规则**：每对必须在两侧实际条目范围内；两列序位都必须**严格递增**。
  越界、重复、交叉（一列序位倒退）都会返回 **400** 并给出具体原因
  （如 `锚点无效：第 2 个锚点 (3:2) 与前一锚点 (1:3) 交叉：两列序位必须同时严格递增`）。
- **对齐方式**：首锚点之前、相邻锚点之间、末锚点之后的各段，仍分别按现有的
  最低代价单调对齐；锚点本身作为强制配对行按顺序拼接——**即使两侧文本差异
  很大（代价 1.0）也绝不跳过锚点**。锚点之外的其他条目照常可能显示为
  「缺对白稿 / 缺字幕」。
- **结果标识**：结果表中锚点行带紫色「锚点」徽标与底色，汇总区显示锚点数；
  CSV 导出额外增加「锚点」列，锚点行标记为 `锚点`。
- **未提供锚点时，对齐结果、接口字段与 CSV 表头均与原来完全一致。**

页面与接口均在同一地址：启动后浏览器打开 **http://localhost:8000**
（端口可改，见上文「修改端口」，例如 `APP_PORT=9000 docker compose up -d --build`
后访问 http://localhost:9000 ）。

API 调用时 `/api/align` 与 `/api/export.csv` 均接受可选的 `anchors` 数组：

```bash
curl -s -X POST http://localhost:8000/api/align \
  -H 'Content-Type: application/json' \
  -d '{"script":"第一行\n第二行\n第三行",
       "srt":"1\n00:00:01,000 --> 00:00:02,000\n字幕甲\n\n2\n00:00:03,000 --> 00:00:04,000\n字幕乙\n",
       "anchors":[{"script":1,"srt":2}]}'
```

## 对齐算法说明

对两侧条目序列 `A`（对白稿）、`B`（SRT）做 Needleman–Wunsch 风格的全局序列对齐：

- 文本归一化：Unicode NFKC（全角→半角等）+ 小写折叠（casefold），
  再剔除所有**空白**与**标点**（Unicode 类别 Z / P / C），中日韩文字原样保留。
  因此 `你好，世界！` 与 `你好世界` 视为完全相同（代价 0）。
- 匹配代价：`编辑距离(归一化A, 归一化B) / max(长度A, 长度B)`，范围 0~1。
- 跳过代价：任一条不参与匹配，计固定 **0.45**（可在页面调整）。
- 动态规划在整张 `(n+1)×(m+1)` 表上取全局最小值，保证：
  - **全局单调**：对位顺序与两侧原始顺序一致，不交叉；
  - **每条最多匹配一次**，两侧都允许缺项；
  - 重复短句依据其在整段中的先后顺序依次对位，不会都吸到同一条。

距离矩阵由 rapidfuzz(C++) 批量计算、DP 使用 numpy；缺少 numpy 时自动回退到
纯 Python 实现（结果完全一致，仅速度较慢）。

### 规模与限制

- 每侧最多 **2000 条**（单次请求文本各 2 MB 内）；超出会返回 400 并提示拆分。
  常规影视剧字幕（数百至约一千多条）秒级返回。
- 该工具为本地/内网校稿辅助，默认无需鉴权；如需暴露到公网请自行放在
  反向代理与鉴权之后。
